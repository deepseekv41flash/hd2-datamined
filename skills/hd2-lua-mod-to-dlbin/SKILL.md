# HD2 老 Lua mod → 数据路线（dl_bin）等价修复版

固定五步。**侦察阶段全程只读**：不写游戏目录、不碰进程内存、不启动游戏。

## 1 开包（抽载荷 + 解字节码壳）

```bash
python tools/lua_payload_dump.py --patch <path/to/9ba626afa44a3aa3.patch_N> --out <recon_dir>
python tools/lua_payload_dump.py --zip "D:/Downloads/<mod>.zip" --member <子串> --out <recon_dir>
```

输出一张清单：每个 lua 条目是 **source** 还是 **bytecode**；bytecode（`loadstring("\27LJ…")` 壳）
会被解成 `<id>/script.luac` + `script.strings.txt`（表名、字段名、报错文本都还在），并直接高亮关键词。

## 2 读载荷，列出"每一次写入"

- 源码：读作者注释（很多 mod 会写清"改哪个偏移、为什么"）。
- 字节码：读 `strings.txt`；出现 `table_rva / buffer_rva / record_size / flag_offset / offset` 这类词
  ⇒ 它在改**内存里的某张表**；出现 `hknp / material / unit / particles` ⇒ 在改**资源**。
- **先找作者源码树**：脚本头常写 `Generated by build.py from src/<name>.lua`；megapack / 精选 mod 的
  源码仓库里常有同版本 `src/*.lua`（用版本号对齐，例如字节码里出现的 `archive-v15.4.1`）。有源码 = 证据升级。

## 3 归层（按**载体**判定，禁用"不可等价"一词）

| 层 | 老 mod 的写法 | 我们的等价载体 | 判定 |
|---|---|---|---|
| **L1 数据表** | 改内存里 `generated_*_settings` 行内字段 | 同名 `.dl_bin` 同行同字段 | **A · dl_bin 等价**（首选） |
| **L2 实体组件** | 组件块 hashmap → 行 → 字段 | `generated_entities` 组件块 / `entity_deltas` | **A · dl_bin 等价** |
| **L3 资源** | havok 材质 `userData`、unit/mesh/particles/texture | 资源路线：`srkit` 解包 → 改载荷 → `patch_N` | **B · 跨载体等价** |
| **L4 引擎代码/内存** | 改 `.text` / hook / 运行时写内存 | 无（只交付盘上数据/资源） | **C · 不可实现** |

**L3 不是死路**：`physics`（Havok tagfile 载荷，已改过 mass）、`texture`/`material`、`particles`、
`unit`/`mesh` 这几族我们都做过。B 档必须标置信度：同族有实证 = 高；同族但未针对本条验证 = 中。

**反例优先**：报告里必须有一行"**它没有碰 X**"。实例：`StickyGrenadeHandles` 名字像改
`StickyComponentData`，实际改的是物理材质库的 4 字节 `userData`。

## 4 映射到本 build（不许照抄老 mod 的常量）

| 常量 | 做法 |
|---|---|
| 字段偏移 | `python tools/table_dictionary.py`（typelib 字段图）+ `entity_field_set.py show` / `dmg_row_edit.py show` 实证 |
| 期望值表（如 `vanilla_flags`） | **从我们的明文表现算**；照抄必然在别的 build 上 1/2 不匹配 |
| 对象集合（实体 id） | `refs/entity-locid-names.json` 按**名字**反查 id，不抄 lo/hi |
| 行数/行号 | 现算，并列出"会被改的行"清单 |
| 断言式校验 | 数据路线换成：先 dump 原值 → 只改声明字段 → 门禁比对 |

## 5 实现 + 验证（能等价时）

```bash
# 伤害行任意字段（含 4 个状态槽 + element）
python tools/dmg_row_edit.py set --type <T> --damage N --element 0 --slot 0:29:1.0 \
    --host-type <空槽宿主> --out out/x.plain --seal
# 实体组件任意字段
python tools/entity_field_set.py set --block <容器type> --key <实体> --field 0x.. --type u64 --value 0x..
# 战备行（含 +0xA8/+0xF8 包声明）
python tools/stratagem_package.py --row "MISSIONS. REINFORCEMENT BEACON" --set-a8 0x..
# 装盘 / 回滚
python tools/dlbin_deploy.py install --file <name> --sealed out/x.dl_bin   (游戏必须关着)
python tools/dlbin_deploy.py restore --file <name>
```

必须同时给出：哈希未变、封包 sha256、盘上回读、**一条命令的回滚**。

## 6 报告骨架（照抄）

`包结构 → 它改了什么（每次写入一行，含"没碰什么"）→ 本 build 字段映射 → 能否等价（L1–L4）→
修复版产物 → 三态表`。完整模板见仓库
`docs/cases/PLAYBOOK-LUA-MOD-TO-DLBIN.md`（含四个样板案例与工具矩阵；
**C 档怎么写才算填满**见其 §6.1 —— 逐层排除表 + 卡点 + 带实测值的替代 + 残余差距）。

## 7 边界

- 不改 `.text`、不做进程内存补丁 —— 我们只交付**盘上数据/资源**路线。
- L3 一律记 **B · 跨载体等价**（给资源路线），**不许**写成"不可等价"；只对 L4 写 **C · 不可实现**，
  且 C 档必须给「卡点 + 最接近替代 + 残余差距」，样板见 PLAYBOOK §6.1（**代码型**：P-11 Self-Heal 运行时事件）/ §6.2（**数据边界型**：锁定锥角）。
- B 档要标置信度：同族有实证=高；同族未针对本条验证=中。
- 实机结论才升级为 `✓ 实机`；门禁只到 `✓ 离线`。
