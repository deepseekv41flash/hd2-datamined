## 1. 两张表在哪里、怎么验哈希

| 文件 | 明文大小 | 结构 | 内容哈希闸门 |
|---|---:|---|---|
| `data/game/generated_projectile_settings.dl_bin` | 96,604 | `4 + 24 + 16` + **355 行 × 272 B** | `946A4FE5FAAAE076` |
| `data/game/generated_explosion_settings.dl_bin` | 68,156 | `4 + 24 + 16` + **424 行 × 152 B**（后有附加块） | `2ABCD21D2536373D` |

- 两个文件都受同一道 **MurmurHash64A** 内容闸门（`game.dll` 烘焙），**保哈希手法与实体表相同**。
- 两张表**行间没有 padding、文件尾也没有余量** ⇒ 校正字写在**无主行**的一个「8 字节对齐全零字」里。
- **行基址 ≡ 4 (mod 8)**（44），步长是 8 的倍数 ⇒ **行内只能用 4、12、20… 这类偏移**承载校正字。

## 2. 射弹行（272 B）已知字段

| 行内 | 类型 | 含义 | 证据 |
|---|---|---|---|
| `+0` | u32 | **射弹 type id**（表内键，不是行号） | 遍历 355 行 |
| `+24` | f32 | 口径 | 与 wiki 对照 |
| `+28` | u32 | 弹丸数（颗粒/破片） | 同上 |
| `+32` | f32 | 初速 m/s | 同上 |
| `+36` | f32 | 质量 | 同上 |
| `+60` | u32 | **伤害行 id**（→ damage 表） | AR-23 弹→116 ✓ |
| **`+144`** | u32 | **命中爆炸 type id**（0 = 不炸） | 见 §4 |
| **`+156`** | u32 | **到期/飞出爆炸 type id**（0 = 不炸） | 见 §4 |

`+144` 的判定依据：166 个非零行里只有 1 个恰好等于自己的伤害行 ⇒ 不是伤害引用；而名字逐条对得上语义
（40mm HE 弹 → `Grenade_40mm_HE`、火箭 → `HeavyRocket`、Eruptor(41) → `JarPhoenix_20mm`(158)、弩箭(253) → `Crossbow_Bolt`(59)）。

## 3. 配方 A：换弹头（整行 272 B 拷贝）

老路线（b9/b21/b32）的离线版：**把源弹丸的整行拷到目标弹丸行上，保留目标自己的 `+0`**。

```
python tools/proj_copy_row.py --plain <vanilla_projectile_plain> \
    --source-type 41 --target-type 180 \        # R-36 Eruptor 弹 → JAR-5 Dominator 弹
    --host-type 291 --host-offset 0x44 \        # 无主行里付哈希校正字
    --out out.plain
```

- **实机**：主宰从「不炸」变成「会炸」✓✓（主宰原弹 `+144 = 0`、`+156 = 0`）
- 主宰弹与 Eruptor 弹的弹道**本来相同**（1 颗 / 180 m/s / 口径 15 / 质量 100），两行只差 **36 字节** ⇒ 单一变量
- ⚠ **`fire +0`（主弹丸字段）不是杠杆**：把它从 180 改成 41 之后，既不炸、穿甲也没变（实测 ✗）。
  整匣换弹武器的实际弹丸由**弹匣/弹药系统**引用，`fire +0` 只是身份字段的遗留（也解释了 Halt `fire +0 = 0` 照样开火）

## 4. 配方 B：换爆炸（射弹行 `+144`/`+156`）

老路线 b40/b41 的离线版：**只改这两个格子**，把爆炸换成任意爆炸 type。

```
# 同一次 proj_copy_row 里加 --set（拷贝后再覆盖）
--set 0x90:178 --set 0x9C:178        # +144 / +156 = ExplosionType_GasGrenade
```

- **实机**：命中处出现**绿色毒气云 + 中毒** ✓✓（毒气爆炸 `178`：内/外/冲击波半径 2/7/7 m、伤害行 461 = 3 伤害、状态 43/45 各 100）
- 观感跟 **type** 走，而**毒气的绿雾是基础状态资产**（永远在包里）⇒ 不需要携带任何毒气装备 ✓
  对照：`EMS 电场 180`、`爆裂铳火球 380` 的资产**不常驻**（不带装备就是占位符 ✗）

## 5. 配方 C：加破片（爆炸行 `+80` / `+84`）—— ★ 本线最大的新能力

| 爆炸行 | 类型 | 含义 |
|---|---|---|
| `+0` | u32 | 爆炸 type id |
| `+4` | u32 | 伤害行 id |
| `+16/+20/+24` | f32×3 | 半径三元组：**内 / 外 / 冲击波**（米） |
| **`+80`** | u32 | **破片数量** |
| **`+84`** | u32 | **破片射弹 type id** |

> 半径三元组的口径（与 `EXPLOSION-VISUAL-26088801.md` §1 一致，旧版本文档曾误写成「内/中/外」）：
> **`+20`（外）才是实际结算圈**——`+16` 内全额、到 `+20` 衰减到 0；**`+24` 只是视觉冲击波**，不参与判定。

```
python tools/expl_set.py --plain <vanilla_explosion_plain> --type 178 \
    --set 0x50:30 --set 0x54:204 \        # 30 颗破片，破片射弹 = 204
    --host-type 275 --host-offset 0x34 --out out.plain
```

- **实机**：毒气弹现在**撒破片** ✓✓ —— 证据两条：
  1. 毒气爆炸自身只有 **3 伤害** ⇒ 打脚底致死不可能来自爆炸；
  2. 用户在**十几米外**（远超 7 m 爆炸半径）**仍受伤** ⇒ 只能是破片飞出去了
- 参照数据：`JarPhoenix_20mm 158` 与 `Flak_20mm 381` 都是 **30 × 204**；破片射弹 `204` = 1 颗 · **30 m/s** · 伤害行 198（**110 伤害 / AP 3-3-2-0**）
- ⇒ **破片完全由数据决定，且可以任意加/改**。这条正是当年 b19 想验而没验成的结论

## 6. 老路线为什么当年没找到爆炸表（复盘点）

`docs/routes/p3a-explosion-shrapnel.md` §7 原文：**五次定位全败，破片实验一次都没执行**
（`M8: explosion edit APPLIED` 出现 **0** 次）。

根因链（文档自己标注"全部为我的实现缺陷"）：

```
188×  explosion container not in the +/-512 KB window; falling back to the allocation walk
187×  explosion allocation walk paused (time slice)
18600+ diagnostic read refused (24 B): diag budget/per-frame cap reached
  1×  explosion container not found at any allocation start (edit skipped)
```

| 环节 | 缺陷 |
|---|---|
| 窗口扫描 | 没有"已扫过"标记 ⇒ 每帧重扫 1 MB |
| 后果 | 吃光每帧诊断额度 ⇒ 连 24 B 的读都被拒 |
| 后果 | 分配区遍历每帧只能挪几步 ⇒ 永远走不完 |
| 结局 | 报"未找到"并放弃 ⇒ 编辑从未发生 |

还有两条叠加因素：① 当时读 `+56` 当 `life_time`（我们 build 两行都是 0，真字段是 `+0x34`）；
② 偏移表跨 build 照抄（build 24826606 的 `+56/+136/+148/+152/+160`）。

**今天为什么一次就成了**：不再内存扫描，改为**离线读文件 + 用射弹行 `+144` 反查爆炸 type**。

## 7. 组合：可切换弹头（实机 ✓✓）

主宰（`JAR-5 Dominator`）：

| 模式 | 弹丸 | 命中爆炸 | 效果 |
|---|---|---|---|
| A | 射弹 `180`（自己那行，拷了 Eruptor 弹头） | `158` JarPhoenix | 橙色爆炸 + 30 破片 |
| B | 射弹 `9`（无主行，拷了 Eruptor 弹头） | `178` GasGrenade | 绿色毒气云 + 中毒 + 30 破片 |

实体侧只两格：`WeaponData +184 = 8`（ProgrammableAmmo）· `ProjectileWeapon +576 = 9`（备选弹）。

- 备选弹**只贡献伤害 + 状态 + 爆炸引用**，弹道来自主弹行 ⇒ 两个模式手感一致（同为 1 颗 180 m/s 慢弹）
- 无主射弹行的挑选标准（全部离线核对）：**fire 表不引用 + WeaponRounds 不引用 + 不被任何爆炸当破片**（本 build 有 179 个满足）
- 爆炸表里有 **265 行没有被任何射弹引用**，可安全当目标或校正字宿主

## 9. 边界与未解

- **弹头换掉 = 弹道也换**（拷贝是整行）⇒ 想只换效果不换弹道，就只改 `+144`/`+156`（配方 B）
- **爆炸观感跟 type 走**：资产常驻的只有毒气（绿雾）等少数；EMS 电场 / Eruptor 火球不常驻
- `+144`/`+156` 之外，射弹行里还有一批未解字段（`+4/+8` 名称哈希、`+52`、`+112/+116`、`+172/+176`、`+204`、`+244`）⚠
- 爆炸行尾部（`+28…+148`）大部分未解 ⚠；`+88`/`+92` 疑似"冲击波/音效"档位
- 破片射弹的**散布/寿命**是否受别的字段控制 ⚠ 未测（可在破片射弹行上再套配方 A）
