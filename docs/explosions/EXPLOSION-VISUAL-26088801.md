# 爆炸视觉：粒子字段 · 整行克隆 · `+0xA8` 跨包加载

> **build `26088801` 实测**（2026-10-23，全部为**改数据文件**路线：不碰进程内存、不需要 Lua/FFI/注入/DLL）。
>
> **一句话**：换任意外观 = ①把供体爆炸的**整行**克隆到无主行 ②弹丸 `+144` 指向该行
> ③把使用者的 `+0xA8` 改成**供体资源所在的那个包**。三步都是纯数据。

## 1. 爆炸行字段图（补齐 SSEO 没标的三组成员）

ExplosionSettings：步长 **152 B**，`+0` = 爆炸 type id（1..424，全表是排列）。

> ⚠ **行区起点的正确说法**：**绝对文件偏移 `44`（= `0x2C`）= payload + 16**。
> 早期本文写成"行基址 = payload + 44"，那是把**绝对偏移 44** 误写成了"payload + 44"（后者是绝对 72），**已更正**。
> 判据（可自行复算，明文 `generated_explosion_settings.dl_bin`，唯一 LDLD 块 `payload @ 0x1C`）：
> 从**绝对 44** 起按 152 B 取 424 行，`+0` 得到 `1..424` 的**精确全排列**；
> 从绝对 72（payload+44）起取，**424 行全是 0**。
> `expl_set.py` 的 `BASE = 44` 是对的 —— 它按绝对偏移寻址。

| 偏移 | 类型 | 含义 | 证据 |
|---|---|---|---|
| `+0x00` | u32 | **爆炸 type id** | 424 行 = 1..424 的排列 |
| `+0x04` | u32 | 伤害行 id | SSEO / HD2Runtime |
| `+0x10/+0x14/+0x18` | f32 | 内 / 外 / 冲击波半径（m） | 实机多次 |
| `+0x1C` | f32 | 锥角 | — |
| `+0x20` | f32 | 震屏半径 | — |
| **`+0x28`** | u32 | **payload 相对偏移 → 尾部震屏列表** | 见 §2 |
| **`+0x2C`** | u32 | `0` 或 `0xFFFFFFFF`（空表哨兵，与 `+0x28` 同步） | 同上 |
| **`+0x30`** | u32 | 震屏条目数（0 / 1 / 2） | 同上 |
| **`+0x38`** | u64 | **粒子特效资源 file_id** | 330 / 424 行命中 `particles` 资源 |
| `+0x40` | u32 | 未知，32 位哈希形态（211 个不同值） | **未解** |
| `+0x50` | u32 | 破片数量 | 实机（毒气爆炸加 30 颗破片，7 m 外受伤）|
| `+0x54` | u32 | 破片射弹 type | 同上 |
| `+0x78` | u32 | 电弧 type | SSEO |

## 2. `+0x28/+0x2C/+0x30` 是震屏列表（结构证明）

尾部是一张 **458 个 8 字节条目**的表，而**全表 424 行的 `+0x30` 之和 = 458**（精确相等）。
条目只有 **16 个不同值**，其中 10 个直接按 `file_id` 命中 **`camera_shake`** 资源 ⇒ 判定为震屏引用列表。

## 3. ★ 只改 `+0x38` 完全不管用（四次反例）

| 爆炸类型 | `+0x38` 改成 | 结果 |
|---|---|---|
| 343（原生 `0xA82CA988`） | `0x1A1CEC42`（380mm 的粒子）| 什么都没有 |
| 343 | `0x1678CC48`（凝固汽油火粒子）| 什么都没有 |
| 343 | `0x6D2BAD78`（**158 的粒子，已知能画**）| 什么都没有 |
| 343 | `0x5743ACE6`（**在它自己包里**）| 什么都没有 |

**四连否**：副本数（28 份，与原生相同）、所在包、是否常驻 —— 全都不是判据。
**只换粒子字段 → 引擎不画。**

## 4. ★★ 正确做法：整行克隆

来自 memmod 时代 `b47/b48/b49` 的配方（那次是写进程内存，**文件版同样成立**）：

```
① 挑一个"无主行"（无射弹引用）
     空白  17 / 28 / 237 / 302      眩晕  233 / 220 / 323 / 335
     火焰  409 / 32 / 69 / 49       毒气  156 / 177 / 270
② 把供体爆炸的 [4, 152) 字节抄进去，★ 保留目标自己的 +0（type id）★
③ 只改需要的那几处：+4 伤害行 · +0x10/+0x14/+0x18 半径 · +0x20 时长
④ 弹丸行 +144 = 克隆行自己的 type id
```

原文（`b48-report.md`）：

> 克隆继承了 380 除 `+0` 和那几处写入之外的**全部字段**，包括它的伤害类型和粒子字段
> —— **正是这种继承让视觉驻留**。

⚠ **实现坑**：一次命令里既写整块 hex、又写落在块内的字段，会互相覆盖。
`plain_edit.py` 的 G4 会正确拒写 —— 做法是**先把字段改好，再合成一个 hex 块**一次写入。

> **无主行账本（`26088801` 现算）**：424 条爆炸行里 **265 条无主**（159 条被射弹
> `+0x90`/`+0x9C` 引用），其中 **98 条伤害行独占**（伤害行只有它自己在用）。
> 随时用 `tools/expl_orphans.py` 重算（`--list` 全表 / `--type N` 单行）——
> 换 build 必须重算，行号不是常量。
> 「把状态送进一片区域」的完整配方见 [STATUS-EFFECTS §7](../tables/STATUS-EFFECTS-26088801.md)。

## 5. ★★★ `+0xA8` = 战备的根包 ⇒ 纯数据的「跨包加载」

**依据**（HD2Runtime `core/assets.lua` 注释原文）：

> EVERY call-in package of a stratagem, as **the game's mission loader requests them for a record entry
> (0x1753080)**: **the row's `+0xA8` package** and its `+0xF8` weapon's package.

**实测四行对照（这才是定因的那一步）**：

| 克隆 | 使用者 `+0xA8` | 结果 |
|---|---|---|
| ✗ | 原值 | 什么都没有 |
| ✓（克隆 380） | 原值 | **灰色半透明方块**（资源缺，但代码路径跑了）|
| ✓（克隆 14） | **改为火粒子所在包** | **火球** ✓ |
| ✓（克隆 14） | **回滚成原值** | **火球消失** |

⇒ **`+0xA8` 是唯一变量。** 它就是一个"声明我要哪个包"的开关，引擎会自己加载。

**无副作用**：精准攻击的信号弹、下落轨迹、命中标记全部正常 ⇒ 战备**自己的资产不是靠 `+0xA8` 加载的**，
所以**替换**根包不会破坏它自身。

## 6. 灰色方块 = 免费的资源探针

引擎用了行里的粒子 id、但资源不在任何已加载的包里 → 画**灰色半透明正方形占位符**。
于是可以区分三种状态：

| 看到 | 含义 |
|---|---|
| 完全没有 | 代码路径没走到（或字段没被采用）|
| 灰色方块 | 走到了，**资源缺** |
| 正常特效 | 资源在 |

## 7. 三条否定证据：**不存在"声明式包依赖"**

想靠改数据"给某个包加一条依赖"，三条实测都堵死：

1. **包头的 56 字节不是依赖表**：实测内容是 `哈希 | 哈希 | 包大小`（4 个包形状一致），无任何包 id。
2. **56 张明文表里，三个资产包零引用**：`0x0296CBE5…` / `0x6104A2FC…` / `0x7ED1F941…` **全表 0 命中**；
   只有战备自己的 `+0xA8` 被 `generated_stratagem_settings` 与 `generated_entities` 各引用一次。
3. **bundle 不是加载单位**：全 build 只有 **30 个 bundle / 9725 个包**且高度重叠
   （任务效果包横跨全部 30 个）⇒ 不存在"同 bundle 顺带加载"。

⇒ **唯一的声明口是 `+0xA8`（以及 `+0xF8` 武器的包）**。

## 8. 资源是多副本的 —— 但这**不是**判据

同一 `file_id` 平均 **5 份副本**（62,915 个唯一 id ↔ 322,711 个条目）。
爆炸 343 的粒子有 **28 份**、380mm 的只有 **1 份**。
⚠ 但 §3 已证明：**28 份的 `0x5743ACE6` 一样不画。** 真正的判据是 **`+0xA8` 声明的那个包加载了没有**。

## 9. 复现步骤（纯离线，`tools/plain_edit.py`）

```bash
# ① 克隆：把供体爆炸的 [4,152) 写进无主行（先生成 hex 块，含要改的字段）
python tools/plain_edit.py --plain generated_explosion_settings.plain \
    --out expl17.plain --allow-wide --set <目标行+4>=hex:<148 字节>

# ② 弹丸：+144 = 克隆行的 type
python tools/plain_edit.py --plain generated_projectile_settings.plain \
    --out proj.plain --set <弹丸行+144>=u32:17

# ③ 战备：+0xA8 = 供体资源所在的包
python tools/plain_edit.py --plain generated_stratagem_settings.plain \
    --out strat.plain --set <战备行+0xA8>=u64:0x6104A2FC6BA869CA
```

两个工具门禁（G1..G6）都会逐项检查：长度、差异集合、重算哈希 == 原值、声明字段读回、其余字节未动、容器自洽。

## 10. 未决

- `+0x40`（211 个不同值的 32 位哈希）语义未解。
- `+0xA8` 是**单个**字段 ⇒ 只能声明**一个**外来包。**第二槽已找到并实机**（2026-10-23）：
  战备行的 `+0xF8` —— 它是**授予武器的 `LoadoutEntry` `+0` id**，引擎会把那把武器的包一并加载。
  `LoadoutPackageComponentData` **不是槽**，而是 `item 实体键 → toc 包` 的解析表。
  详见 [POD-RACK §4/§5](../tables/POD-RACK-26088801.md)。
- `+0xA8` 能否声明**任意**包（不只是含目标资源的包）未测；若可以，它就是通用的"预加载某包"开关。
- 无主行可能被未来更新占用 —— 克隆前必须重新确认该行无射弹引用。
