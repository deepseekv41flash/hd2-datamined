# FAF-14 Spear 高抛弧线 — 纯数据表最小配方（build 26251122）

> 2026-11-02 反证 + 最小化单变量实机链（R6→R20，15 轮）。
> 结论：Spear 的锁定射击可以改成 WASP Artillery 式**完整高抛**，最小只需 **6 格**，
> 且 A 对 / V1 / V2 / `+0xE0` / `+0xE4` / `+0xEC` / `+0xF4` 全部可留 0。
> 关联：`WASP-TRAJECTORY-FIX-26251122.md`（B 对=弧线、`+0xE4`=打转开关的七轮链）、
> `GUIDANCE-MODES-26251122.md`（制导三问 + deviation 拆分细节）。

## 0. 结论一句话

Spear 弹头实体 `0x1A4323835B84CEA7` 的 `SeekingMissileComponentData`，改这 6 格：

| 行内偏移 | 字段（推定） | 原值 | 配方值 |
|---|---|---|---|
| `+0x0C` | 制导启用时间（−1=手动 / 秒） | −1 | **0.01** |
| `+0xB4` | 使能字节 | 0 | **1** |
| `+0xC0` | B 对（弧线角度下限） | 0 | **60** |
| `+0xC4` | B 对（弧线角度上限） | 0 | **75** |
| `+0xE8` | 弧线启动/基础振幅 | 0 | **0.2** |
| `+0xF0` | 弧高倍率 | 0 | **0.8** |

⇒ 锁定射击先 60–75° 爬升、再压向目标（完整高抛），**不打转**；Spear parity 三层原样。

## 1. 为什么"整块搬 deviation"不够（门槛 = `+0x0C`）

- **R7**：把原版 Artillery 弹头 `0x1597AF7289E1BE93` 的 68 B deviation 块**逐字节**搬进 Spear 弹头
  （17 处 u32，1 个 tail 宿主，G1–G9 全 PASS）→ 实机**仍是直线**。
- 本 build 的 typelib 可解出逐字段布局（无字段名，但有 offset/size/type id）：
  - `SeekingMissileComponent`（type `0x2DD927CF`）= **272 B / 42 个成员**；
  - `SeekingMissileDeviationSettings`（`0x0C15CCB0`）= **68 B / 13 个成员**：
    `u8 +0x00; f32 +0x04/+0x08/+0x0C/+0x10; CApiVector3 +0x14; CApiVector3 +0x20; u8 +0x2C; f32 +0x30/+0x34/+0x38/+0x3C/+0x40`
    （行内绝对偏移 = `+0xB4` + 结构偏移，与七轮实机链推出的偏移表完全一致）。
- 用同一办法把 Spear 弹头实体与 WASP Artillery 弹头实体**逐字段 diff**：R7 之后飞行相关差异只剩
  `+0x0C`（−1 vs 0.01）、`+0x4C`（100 vs 80）、`+0x58`（10 vs 30）、`+0x5C`（13 vs 35），
  另有尾迹 EffectSetting 与 `ProjectileClusterComponentData`（空中爆裂：ExplosionType 87 / AbilityId 2626）；
  6 个共享组件（SensorEye / ThrusterGroup / Faction / Attachable / Ability / Detector）**逐字节 0 差异**。
- **R8**：把这 4 格全部对齐 Artillery（17→4 处写入）→ 实机**高抛**。
- **R9**：只保留 `+0x0C`=0.01，`+0x4C/0x58/0x5C` 还原 Spear 原值 → 仍**高抛**
  ⇒ 门槛是 `+0x0C`：Spear 原值 −1 表示"手动启用制导"，开火瞬间制导就把导弹钉在目标视线上，
  deviation 的 60–75° 抬升角根本没机会生效；改成 0.01 s 自动启用后弧线才出现。

## 2. 最小化链（R10→R20，每轮单变量/单组，全部实机）

| 轮 | 改动（相对上一轮） | 实机结果 | 判读 |
|---|---|---|---|
| R10 | deviation 块只留 `+0xB4`、B 对 60/75、`+0xE0`、`+0xE4`=2 | 直射 | B 对不够；被清零的 A/V/尾部至少一组必需 |
| R11 | + 恢复 A 对 −8/8 + V1 5/10/5 + V2 10/15/10（尾部仍 0） | 直射 | A/V 单独不够 |
| R12 | + 恢复尾部 4 格（A/V 仍 0） | **完整高抛** | 尾部组够 ⇒ A/V 可丢 |
| R13 | 只剩 `+0xF0`=0.8、`+0xF4`=0.05 | 直射 | `+0xE8/+0xEC` 至少一格必需 |
| R14 | 只剩 `+0xE8`=0.2、`+0xEC`=0.05 | **短弧**（上升很短） | 弧线机制在跑，幅度被限 |
| R15 | R14 + `+0xF0`=0.8（F4 仍 0） | **完整高抛** | **`+0xF0` = 弧高倍率** |
| R16 | R15 去掉 `+0xE8`（留 EC+F0） | 直射 | **`+0xE8` 必需**（弧线启动/基础振幅） |
| R17 | R15 去掉 `+0xEC`（留 E8+F0） | **完整高抛** | `+0xEC` 不需要 |
| R18 | R17 去掉两个使能字节（`+0xB4`=0、`+0xE0`=0） | 直射 | 至少一个使能字节必需 |
| R19 | R18 只恢复 `+0xB4`=1（`+0xE0` 仍 0） | **完整高抛** | **`+0xB4` 必需、`+0xE0` 可丢** |
| R20 | R19 再把 `+0xE4` 归 0（Spear 原值） | **完整高抛、不打转** | **`+0xE4` 不需要** |
| R21 | R20 把 B 对两格**互换**（`+0xC0`=75、`+0xC4`=60） | 与 R20 看不出区别 | 两格**对称**：引擎按"角度区间"处理，写在哪格不影响表现 |
| R22 | R20 把区间**拉宽**成 `+0xC0`=20、`+0xC4`=75 | **每发弧线高度都不一样** | B 对 = **发射角随机区间 [下限, 上限]**，实际角度在区间内随机取值 |

⇒ 最终最小：`+0x0C` + `+0xB4` + B 对（2 格）+ `+0xE8` + `+0xF0` = **6 格**，其余 deviation 字段全 0。
B 对的"分工"结论：`+0xC0`/`+0xC4` 是**同一条角度区间的两个端点（下限/上限）**，
互换顺序无影响（R21 ✓），区间越宽逐发差异越大（R22 ✓），区间中心决定平均弧高。

## 3. 字段语义模型（本 build 实机确认部分）

| 偏移 | 语义 | 证据 | 档位/备注 |
|---|---|---|---|
| `+0x0C` | 制导启用时间（−1=手动 / 秒） | R7→R8→R9 | Spear 必须改 0.01 才让弧线生效 |
| `+0xB4` | deviation 使能字节 | R18→R19 | 必需；值语义未测（只要 1 还是任意非零？） |
| `+0xC0/+0xC4` | B 对：**发射角随机区间的下限/上限**（对称，互换无影响） | WASP R6；本链 R21/R22 | 60/75=完整高抛随机区间；10/15=平射；20/75 实测**逐发高度不同**（区间越宽差异越大）；区间中心=平均弧高 |
| `+0xE8` | 弧线启动/基础振幅 | R14/R16 | 缺→直射；0.2 为 Artillery 值 |
| `+0xF0` | 弧高倍率 | R13/R14/R15 | **0.8=完整高抛**；0=短弧；0.5=Burst 中弧；0.01=P-92 无弧 |

| A 对、V1、V2、`+0xE0`、`+0xEC`、`+0xF4` | 与本弧线无关（至少可全 0） | R10→R20 | 可留 0 |

## 8. 方法学备注

- 本轮的关键工具是 **typelib 逐字段解析**：`TypeLib.members(type_id)` 能给出每个成员的 offset/size/type id，
  类型 id 可用 `djb2 名字表`（`D:\mod\filediver-dl-type-names.txt`，`h=h*33+b; id=h-5381`）反查名字 —— 
  即使 typelib 被剥掉字段名，也能把 272 B 的行结构精确画出来；
- 每轮都是 `entity_batch_set.py`（tail 宿主保内容哈希）+ G1–G9 + `seal-key` + `dlbin_deploy install` + `open-key` 回读；
- **教训**：一轮"已装盘"的表述必须以 `dlbin_deploy.py status` 的 sha 为准 —— 
  本轮曾把尚未装盘的 R20 提前写进报告，用户实测的其实是 R19，随后已纠正并补装 R20；
- **锚点按 build**：`generated_entities` = `0x8E49771B181FFAA1`；
  `generated_projectile_settings`（26251122）= `0x113A5833529A71B5`（旧文档的 `0x946A4FE5FAAAE076` 是 26088801）。
